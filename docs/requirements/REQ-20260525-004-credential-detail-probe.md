# REQ-20260525-004 上游凭证详情编辑合并与可用性探测

状态：Done  
日期：2026-05-25  
上游来源：用户反馈“已录入凭证界面，希望点击凭证可以弹出凭证详情页面，展示凭证所有详情，包括但不限于用量；不需要单独展示界面，编辑界面和详情界面合并；增加联通性测试按钮，发送简单 prompt，让上游回复，检测凭证是否可用，并记录可用性。”

## 背景

当前上游凭证页面主要围绕新增、列表与部分运行状态展示，已录入凭证缺少一个统一的详情入口。用户希望列表中的凭证可直接点击，打开一个合并详情与编辑能力的弹窗，而不是再新增独立详情页面。同时，凭证是否真实可用需要通过主动联通性测试确认，并把结果沉淀到系统中，供后续排序、治理、告警和人工判断使用。

## 目标

- 在上游凭证列表中点击凭证行或凭证名称后打开详情/编辑合并弹窗。
- 弹窗展示凭证完整详情，包括基础信息、绑定厂商/协议入口、运行状态、健康/可用性、最近探测结果、用量摘要和必要的安全脱敏信息。
- 保留编辑能力，详情和编辑在同一个弹窗内完成，不新增独立展示页面。
- 新增“联通性测试”按钮，由后端使用该凭证发送一个简单 prompt 到上游 chat/messages/generateContent 类能力，判断凭证是否可用。
- 探测结果需要持久化记录到凭证上，包括可用/不可用、时间、延迟、上游请求 ID、错误摘要和返回摘要等。

## 范围

- Admin 上游凭证 API、服务、响应结构。
- 上游凭证实体必要字段与 Liquibase 迁移。
- 上游凭证前端页面与对应测试。
- 最小 chat 类联通性探测；优先覆盖现有 OpenAI-compatible、OpenAI Direct、Anthropic Direct、Gemini Direct 路径。

## 非目标

- 不新增独立凭证详情路由或详情页面。
- 不在前端展示密钥明文。
- 不实现所有 provider 的全量功能 smoke；本轮只做简单 prompt 的 chat 类可用性探测。
- 不把探测按钮变成后台定时巡检。
- 不重构现有路由选择、模型策略和计费系统。

## 方案

1. 后端为凭证增加探测状态字段：最后探测状态、时间、延迟、错误摘要、返回摘要、上游请求 ID。
2. Admin 凭证详情响应补齐运行详情与用量摘要；如现有数据源只能提供部分聚合，先展示可获得的真实字段，并明确为空值。
3. 新增凭证联通性探测 API：`POST /admin/credentials/{id}/connectivity-test`。
4. 探测服务复用现有 credential material 解密、provider runtime profile 和 chat runtime/HTTP 能力，避免在前端拼接上游请求。
5. 前端将凭证列表的行/名称作为详情入口，打开同一个弹窗展示详情、编辑表单和联通性测试结果。
6. 探测成功或失败后刷新凭证列表/详情，展示并记录最新状态。

## 风险

- 真实上游探测会消耗少量 token 或额度，需要 prompt 足够短。
- 部分凭证缺少可用模型、站点或协议入口时无法探测，应返回明确失败并记录。
- 不同厂商错误结构不一致，错误摘要必须脱敏且限制长度。
- 如果探测直接使用某个默认模型，可能出现“凭证可用但默认模型不可用”的误判；需要优先使用凭证绑定站点/能力快照中的模型，缺失时才使用保守默认。

## 验收标准

- 上游凭证列表可点击已录入凭证并打开详情/编辑合并弹窗。
- 弹窗可展示凭证基础信息、绑定信息、健康状态、最近探测结果和用量摘要。
- 弹窗内可继续编辑并保存凭证。
- 点击“联通性测试”会调用后端 API，成功/失败都会记录到凭证并刷新展示。
- 探测不会泄露密钥明文。
- 后端和前端定向测试通过，前端 typecheck 通过。

## 测试边界

- 后端：凭证详情响应、探测成功/失败状态记录、字段脱敏。
- 前端：点击列表打开详情弹窗、保存编辑、触发联通性测试并展示结果。
- 类型检查：`cd web; bun run typecheck`
- 真实上游 live smoke：仅在本地已有真实凭证且用户允许消耗少量额度时执行。

## 实现结果

- 已将 API Key 类型“已录入凭证”的名称与查看入口改为打开“详情即编辑”弹窗。
- 合并弹窗同时展示只读详情、用量摘要、最近联通性探测、运行错误、可编辑字段和保存按钮。
- 新增 `POST /admin/credentials/{id}/connectivity-test`，使用保存的凭证向上游发送极短 chat 类 prompt，并将结果写回凭证。
- 凭证表新增最近探测状态、时间、延迟、错误摘要、响应摘要、上游请求 ID 和探测模型字段。
- Admin 凭证详情响应与统一 inventory 响应均透出最近探测字段。
- 联通性状态使用明确结果：`AVAILABLE`、`UNAVAILABLE`、`UNSUPPORTED`，失败不会伪造可用响应。
