# REQ-20260521-004 上游凭证入口统一与官方账号概念澄清

## 背景

当前控制台已经把 Codex 接入收敛进“上游凭证”语境，但入口和命名仍然割裂：

- `上游凭证` 页同时存在 `创建凭证` 与 `导入 Codex 凭证` 两个一级动作，仍然像两套入口。
- 一级导航保留 `官方账号会话`，容易让人误以为它和上游凭证是平级的两类资源。
- 从产品概念看，Codex / Copilot / Gemini CLI 这类官方账号本质上也是上游凭证的一种，只是认证材料和运行态不同。

用户要求：

1. 导入 Codex 凭证和创建凭证放在一个入口。
2. 解释并弱化“官方账号会话”与“上游凭证”之间的概念重叠。
3. 控制台页面不再保留这类概念解释性文案，改为只保留必要操作、状态与错误反馈。

## 目标

- 将“创建凭证”和“导入 Codex 凭证”收敛为单一入口。
- 让控制台信息架构表达：官方账号属于上游凭证接入的一种，不再表现为独立产品概念。
- 不再把官方账号运行态作为控制台一级活跃能力；如需运营或排障，只保留后端/API 与内部说明层面的最小可见性。
- 删除控制台现役页面中为解释产品边界而新增的说明性文案，不在页面正文继续解释“为什么这样设计”。

## 范围

- `web/src/features/credentials/credentials-page.tsx` 的入口动作与交互。
- `web/src/app/navigation.ts`、`web/src/components/app/app-shell.tsx` 的导航与命令搜索命名。
- `web/src/features/accounts/oauth-sessions-page.tsx` 及相关前端文案。
- 现役前端页面中的解释性提示块、说明段落与默认解释文案。

## 非目标

- 本轮不合并后端 `UpstreamCredentialEntity` 与 `UpstreamAccountEntity`。
- 本轮不重写官方账号导入链路、配额刷新链路或 runtime 选择逻辑。
- 本轮不新增新的后端 API。
- 本轮不删除表单字段 label、数据字段 `description`、运行期错误提示与校验反馈。

## 风险

- 如果只改入口、不改命名，用户仍会把 `官方账号会话` 理解成独立接入体系。
- 如果文档没有同步说明“控制台下线但后端保留”，容易让人误判官方账号导入、冻结、刷新和排障链路已经一并删除。
- 如果把错误提示或操作反馈误删成“解释文案”，会削弱页面可操作性与排障能力。

## 验收标准

- `上游凭证` 页只保留一个一级新增入口，用户可从该入口进入普通凭证创建或 Codex 官方账号导入。
- 导航和页面信息架构不再把 `官方账号会话` 表述成与上游凭证平级的另一套接入概念。
- 历史文档与说明页能解释其定位是“后端保留的运行态 / 导入后管理能力”，而不是当前控制台主入口。
- 现役控制台页面不再展示这类概念解释性正文，仅保留必要标题、操作、状态与错误反馈。
- 前端 typecheck 与相关测试通过。
