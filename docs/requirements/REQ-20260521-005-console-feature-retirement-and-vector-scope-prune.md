# REQ-20260521-005 控制台重复功能下线与向量能力范围收窄

## 背景

用户在 2026-05-21 明确提出，当前控制台和能力面里有一批功能“过于重复”或“不够实用”，希望直接删除，包括：

1. `官方账号运行态`
2. `能力矩阵`
3. `Native 命名空间兼容`
4. `Provider 参考差距`
5. `站点档案`
6. `成本路由策略中心`
7. `向量检索排障沙盒`
8. `向量 API`

其中前 7 项大多表现为控制台导航、页面、调试视图或治理视图；`向量 API` 则已经深入到公开协议兼容面、OpenAPI、文档、Responses `file_search` 绑定链路和本地异步资源实体，不再只是“删一个页面”的级别。

## 目标

- 将用户判定为重复、低价值或偏离主线的控制台功能从产品面中移除。
- 继续收窄项目主线，聚焦对话、streaming、tools、多模态与必要的认证/审计/路由支撑能力。
- 在开始删除前，明确哪些删除只影响控制台信息架构，哪些删除会影响后端管理 API 或公开兼容 API。

## 范围

### 包含

- 控制台导航、路由、页面、命令搜索中的对应入口与功能页。
- 与这些页面直接绑定的前端交互、文案、空状态和测试用例。
- 如用户确认“彻底删除”，则继续覆盖对应 Admin API、后端治理服务、公开向量 API、OpenAPI 与文档事实源。

### 不包含

- 在删除边界未确认前，不直接删除 `vector_stores` 公开 API、Responses `file_search` 绑定和相关持久化能力。
- 在删除边界未确认前，不直接删除 `官方账号` 导入链路的后端实现。

## 当前待确认决策

本次请求至少存在两层删除粒度，需要先确认：

1. **控制台下线**：只删除导航、页面、路由和调试视图，不再对用户暴露这些入口。
2. **能力彻底清理**：除了控制台下线，还同步删除对应 Admin API、服务、公开协议入口、OpenAPI、文档、测试和持久化逻辑。

其中：

- `官方账号运行态` 若彻底删除，意味着不仅要删 `/console/accounts*`，还要评估 `/admin/accounts*`、`/admin/accounts/import-auth-json`、官方账号 refresh/freeze/quota 逻辑是否一起清理。
- `向量 API` 若彻底删除，意味着不仅要删 `/console/vector-stores`，还要评估 `/v1/vector_stores*`、`Responses file_search` 本地绑定、`GatewayAsyncResourceService` 中的 vector store 资源与相关 public docs 是否一起下线。

## 本轮执行假设

在用户尚未进一步明确“彻底删除后端/API”之前，本轮先执行低风险版本：

1. 删除控制台中的功能入口、导航、路由、页面、页内跳转和对应前端测试。
2. 对历史书签和旧路由使用前端 redirect，避免用户进入 404。
3. 暂不删除 `/admin/accounts*`、`/admin/provider-sites*`、`/admin/cost-routing*`、`/admin/vector-stores*`。
4. 暂不删除公开 `/v1/vector_stores*`、Responses `file_search` 本地绑定、OpenAPI 兼容实现和相关持久化实体。

## 本轮文档清理口径

- 文档侧先删除或收紧把上述能力写成“当前控制台主入口”“当前主推能力”“默认运营面”的表述。
- 对仍需保留的后端/Admin/API 文档，统一补充“控制台已下线，后端/API 暂保留”的状态提示。
- 本轮按用户要求只修改 `docs/`；`tasks/`、`web/`、`src/` 不在本次写入范围内。

## 风险

- 如果只删页面不删后端，控制台会更简洁，但仓库内部仍然保留较多“不可见能力”与维护成本。
- 如果直接彻底清理 `向量 API`，会影响当前已经归档为功能性服务 API 支撑面的多份需求、任务、公开文档、OpenAPI 和测试。
- 如果直接彻底清理 `官方账号运行态`，需要重新定义 `auth.json` / token 类官方账号材料是否还允许导入，以及之后归入哪个接入模型。

## 验收标准

- 本轮首先完成删除边界确认，并形成明确 task spec。
- 对于确认删除的功能，至少做到导航、路由、页面、文案和测试口径一致。
- 如确认彻底删除某项能力，必须同步回写公开文档、OpenAPI、任务状态与残留扫描结果，避免“入口删了但协议还宣称支持”。
- 在本轮仅做 docs 清理时，`docs/index.md` 与相关技术说明页必须明确区分“控制台下线”和“后端/API 暂保留”。

## 实施结果

- 2026-05-21：文档清理阶段先完成 `docs/index.md`、官方账号运行态说明、provider-sites 说明、OpenAI Direct SDK 示例、公开 API 兼容说明等口径收紧。
- 当前已统一为“控制台已下线、后端/API 暂保留”的文档状态；未进入 `tasks/`、`web/`、`src/` 修改。
