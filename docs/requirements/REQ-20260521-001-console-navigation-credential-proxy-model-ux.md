# 控制台导航、凭证、代理与模型目录 UX 收紧

## 背景

当前控制台一级导航全部展开后侧边栏过长；Codex 被拆成独立一级菜单，与实际“接入”域的归属不一致；上游凭证创建后缺少明显编辑入口；代理录入未明确支持主流代理 URL 格式；模型目录中 Alias 映射治理位于目录列表下方，用户需要先滚过模型清单才能治理映射。

## 目标

- 一级菜单支持按分组折叠，默认降低侧边栏高度。
- Codex 接入入口归并到“接入”一级菜单。
- 上游凭证列表提供明确编辑入口，且更新凭证时不强制每次重新提交 secret。
- 代理配置支持常见 `http`、`https`、`socks`、`socks4`、`socks5` URL 格式。
- Alias 映射治理堆叠到模型目录上方。

## 非目标

- 不重做整体导航信息架构。
- 不引入新的前端组件库。
- 不扩展代理链路的复杂鉴权、PAC 或分流策略。

## 方案

- 在 `AppShell` 侧边栏分组标题上增加折叠按钮，折叠状态持久化到 localStorage；没有用户偏好时默认只展开当前路由所属分组。
- 修改 `navigation.ts`，将 Codex 入口移动到接入组，并同步路由面包屑分组。
- 在凭证列表操作区增加“编辑”按钮，跳转到现有凭证详情编辑页；后端更新逻辑改为 secret 可选，只有填写新 secret 时才更新密文和指纹。
- 代理页增加协议选择/示例，一键套用主流代理 scheme；后端保存和拨测校验允许 `http`、`https`、`socks`、`socks4`、`socks5`。
- 模型页先展示 Alias 映射治理，再展示模型目录。

## 风险

- 导航折叠默认行为可能影响用户首次发现入口，需要保证当前路由所在分组自动展开。
- 凭证更新允许空 secret 后，必须避免创建时也绕过 secret 校验。
- 代理 URL 格式只做基础 scheme/host 校验，不代表所有运行时 HTTP client 已完整使用该代理。

## 验收标准

- 侧边栏一级分组可展开/折叠，刷新后保留用户选择。
- Codex 不再作为独立一级菜单展示。
- 上游凭证列表可直接进入编辑页；编辑非 secret 字段时可以保存。
- 代理表单可选择或输入 `http(s)` / `socks` 系列 URL。
- 模型目录页面顶部先看到 Alias 映射治理区域。

## 实现结果

- 已在控制台侧边栏增加一级分组折叠，并持久化展开状态；当前路由所属分组保持展开。
- 已将 Codex 入口归并到“接入”，并同步搜索入口和面包屑归属。
- 已在上游凭证列表和详情弹窗增加编辑入口；后端更新凭证时允许留空 secret 以保留现有密钥。
- 已在代理表单增加协议选择和格式提示；后端保存/拨测支持 `http`、`https`、`socks`、`socks4`、`socks5`。
- 已将 Alias 映射治理视觉顺序调整到模型目录上方。
