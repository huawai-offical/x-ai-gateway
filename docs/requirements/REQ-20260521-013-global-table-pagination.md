# REQ-20260521-013 全局表格分页

状态：Done  
日期：2026-05-21  
上游来源：用户指令“所有的表格都要做分页功能，所有表格默认一页50条，可以更改”

## 背景

控制台和门户中存在大量列表表格，当前多数表格直接渲染完整数据集。随着凭证、账号、请求日志、系统事件、套餐、用户、网络画像等数据持续增加，完整渲染会造成页面滚动过长、交互查找困难，也会影响前端渲染性能。

## 目标

- 所有列表型表格统一具备分页能力。
- 默认每页显示 50 条。
- 用户可以修改每页条数。
- 分页控件使用统一组件，避免各页面重复实现。
- 当数据不足一页时仍保持表格简洁，不强行增加干扰性的说明文案。

## 范围

- `web/src/components/app/` 中新增或扩展通用表格分页组件。
- `web/src/features/` 下所有使用 `<table>` 渲染列表数据的页面。
- 相关前端测试与类型检查。
- 落地范围覆盖账号、上游凭证、模型、网络、运维、请求日志、资源、集成、上游缓存、门户、公开文档和用户域页面。

## 非目标

- 本轮不强制把所有后端接口改为服务端分页；优先落地前端分页，避免影响既有 API 契约。
- 不改变表格列定义、筛选条件、排序语义和详情弹窗功能。
- 不引入虚拟列表或第三方 DataGrid。
- 不把分页状态持久化到 URL 或 localStorage，除非页面已有相同模式。

## 风险

- 页面表格分布较散，容易遗漏非主路径页面。
- 部分表格嵌套在详情弹窗或 tab 中，需要分页状态在数据变化时正确归位。
- 测试中如果直接断言完整数据同时可见，需要同步为分页后的可见范围。
- 静态文档型小表如果也分页，可能降低阅读效率，需要按“列表型表格优先”的边界处理。

## 验收标准

1. 通用分页控件默认每页 50 条，并支持切换每页条数。
2. 数据列表型表格渲染分页后的当前页数据。
3. 首页、账号、凭证、网络、运维、请求日志、资源、集成、用户域、门户等现役页面表格具备分页入口。
4. 数据变化、筛选变化或每页条数变化时，当前页不会停留在无效页。
5. 前端类型检查和相关页面测试通过。

## 测试边界

- `npm run typecheck`
- 表格相关页面的定向 vitest。
- 浏览器轻量检查一个控制台页或在未登录环境中记录限制。

## 实现结果

本轮已完成全量列表型 `<table>` 分页接入：

- 新增 `web/src/components/app/table-pagination.tsx`，提供 `useTablePagination` 和 `PaginatedRows`。
- 默认每页 50 条，支持切换为 25、50、100、200 条。
- 分页状态在数据量变化、当前页越界和每页条数变化时自动归位。
- 账号、上游凭证、模型、网络、运维、请求日志、资源、集成、上游缓存、门户、公开文档和用户域页面的列表型表格均已接入 `PaginatedRows`。
- CSV 导出、筛选、详情弹窗、编辑、删除、手工执行等操作仍使用原完整数据源和原交互逻辑。
- `ProviderPresetTable` 当前是卡片网格，不是 `<table>`，未改造为分页表格。
